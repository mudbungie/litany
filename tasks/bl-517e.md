Round-1 swdev lane. litany 0.0.10 under yog 0.0.38, worker `claude-sonnet-5`.

Two unrelated conversations, on two unrelated projects, made the same first-patch mistake and each lost a step to it. The envelope, verbatim from the transcript:

    *** Begin Patch
    *** Update File: src/pyshop/cart.py
    *** Update File: src/pyshop/cart.py
    @@
         def subtotal(self) -> float:
    -        # BUG: ignores quantity
    -        return self.unit_price
    +        return self.unit_price * self.quantity
    @@
         codes = {"SAVE10": 0.10, "HALF": 0.50}
    -    # BUG: adds the rate instead of subtracting it
    -    return round(total * (1 + codes.get(code, 0.0)), 2)
    +    return round(total * (1 - codes.get(code, 0.0)), 2)
    *** End Patch

Reply, verbatim:

    Exit code: 1
    --- stderr ---
    litany tool apply_patch: update of src/pyshop/cart.py has no hunks

The other conversation did the identical thing on `src/lib.rs` and got the identical sentence. Both then re-sent the same patch with one header and it applied first try.

The refusal is *true* — the first `Update File` section is empty, because the second header closes it — but it describes a section the model does not believe it wrote. What the model did was write one header per hunk, which is a reasonable misreading of a format whose hunks are separated by `@@`. The schema's own description (`tools/apply_patch.json`) is correct and says `'@@' separates hunks`, so the fix is not there.

Expected: name the cause. Something like `a second '*** Update File: <path>' for a file already open in this envelope — separate hunks in one file with '@@'`. The model then needs no second attempt.

Severity p3: recoverable in one step and always recovered here, but it is 2 of 3 first-patch attempts by the shipped worker model, so it is a per-conversation tax rather than a rarity, and the whole cost of fixing it is one sentence.
