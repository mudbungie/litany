Scenario: lane KNOWLEDGE, round 1. Three proposals staged from one conversation. The list a person reads before accepting:

    ID                       LINEAGE  PARENT        STATE  DIFF                             SUBJECT
    ...-3a7ccad2             default  fa9d5d381f9d  fresh  1 file changed, 6 insertions(+)  Excellent. The skill now documents the trustworthiness rule that the user corrected.
    ...-02ec32c8             default  fa9d5d381f9d  fresh  1 file changed, 5 insertions(+)  ## Final Response
    ...-05c5e469             default  fa9d5d381f9d  fresh  1 file changed, 5 insertions(+)  ---

The commit message is the reviewer's terminal response text, and its first line is the subject. A model's terminal response rarely opens with a subject line; two of my three opened with a markdown heading and a horizontal rule. The list is the only place a person triages several proposals, and it told me nothing about two of them — I had to open each.

The first row is not much better: it is a report about the act ("the skill now documents...") rather than a statement of what changes, which is what a subject in a diff list is for.

EXPECTED

Either the reviewer soul states the response format (first line is a short subject, then the rationale — the way a commit message is written), or the lister derives a subject from the diff when the first line is not one (a bare heading, a rule, an empty line), the way a git tool falls back to the changed path.

SEVERITY

p3: the loop works; reading it does not. It compounds with the fact that a person only ever sees this list when they are about to change the policy every conversation in the workspace resolves.
