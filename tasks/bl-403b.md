Operator ruling 2026-09-01, extending bl-f928's: "the conversation should not
be pinned! configuration should be changeable at any time, on any turn." The
whole configuration follows the workflow's precedent: a conversation resolves
the workspace's CURRENT config at every step boundary by default; fork-time
pinning is gone as the default behavior. A step in flight finishes on the
config it started with (resolution is per-hop already).

Live evidence: a deployed workspace's roles moved off an uncredentialed
provider row onto a working one, and existing conversations kept refusing on
the dead row until each was hand-retargeted — the operator had no surface
saying their running conversations were pinned to a dead config.

Keystone (this ball):
- workspace::current_config: governing commit (unchanged ancestry query) ->
  the config/* head that CONTAINS it; exactly one such head -> resolve that
  head's commit (the tip). Not exactly one (a second lineage forked through
  the same commit, or the lineage gone) -> resolve the governing commit
  itself, with a loud notice naming the state and the retarget escape.
- resolve_worker resolves control (soul, providers, manifest, version,
  workflow default, descriptions derivation for child forks) from that
  followed commit, for Agent and Fork sources alike; the workflow mark
  (bl-f928) stays the scoped per-agent override and now pins against tip
  movement exactly as it pinned against retarget.
- child_dispatch's budget gate reads the same derivation; retarget's
  already-governing no-op compares against the followed answer.
- retarget is NOT deprecated: re-scoped to choosing the LINEAGE (and healing
  ambiguity) — following-the-tip is the temporal default within a lineage.
- docs: ARCH §2.2 freeze inversion, §6 intro + mark text, PRINCIPLES,
  TAXONOMY, README; DESIGN_CONFIG_FOLLOW.md is the design artifact.
- tests pinning the freeze are inverted, never deleted.

What pinning still exists, stated honestly in the design: a step in flight
(one hop's resolution); the workflow mark (deliberate per-agent pin); the
dispatch-time tree artifacts (descriptions cut — child ball); and step
records as the diagnostic provenance of what a past step actually resolved
(per-step config provenance recording is a child ball).

Gates: tests (100%, all pass), docs, alignment (ARCHITECTURE, PRINCIPLES,
TAXONOMY coherent).
