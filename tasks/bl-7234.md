`compactor::tools::not_compaction_eligible` matches the nominated path
exactly (folding a leading `./`). `mark_for_deletion` then runs
`git rm -r -q -- <path>`, which removes recursively — so a nomination of
an ANCESTOR of a protected path removes it while the predicate says
nothing. `.` removes the whole worktree including the system slot's three
files; `messages` removes the dispatch entry with the rest of the
transcript.

This bound is not new. It has been the dispatch-entry decline's since
bl-898f, and bl-541b inherited it when it extended the same predicate to
the system slot's files — the ball's own instruction was to extend the
predicate rather than build a second mechanism, so widening the match
shape was deliberately left out of it.

Unobserved in either form. Filed because the argument that closed both
existing cases — the fact is knowable from the path alone (ARCH §2.7) —
covers the ancestor case just as cleanly, and nothing else does: the
landing classifies `dispatch..tip` deletions as the compactor's product
without reading which paths they are.

What it needs decided before it is built: declining an ancestor of the
dispatch entry means declining `messages` wholesale, and shedding the
whole transcript in one nomination may be sanctioned compaction rather
than a defect. If it is, the two classes want different shapes — an
ancestor guard for the system slot's files, an exact match for the
dispatch entry — which is a second mechanism and should be argued for
rather than assumed.

---

The third not-compaction-eligible class landed in bl-c7bb inherits this same bound. `written_by_this_pass` asks `git diff --cached --diff-filter=AM <dispatch> -- <path>` for the exact nominated path, so nominating `summary` (the directory) walks around it exactly as nominating `messages` walks around the dispatch-entry decline — and `git rm -r` then removes the pass's own summary with the rest. Whatever match shape this ball settles on should cover all three classes through the one predicate, since they already share it.
