Every scheduled workflow (ingest.yml, store-scan.yml) ends with two steps: on failure `scripts/alarm.sh red`, on success `scripts/alarm.sh green`. The alarm's state is the open issue titled exactly `unattended run red: <workflow name>` — queried, never stored. Red with none open creates it, mentioning the repository owner (the mention is what sends the notification) and linking the run; red with one open does nothing, so a streak is one notification and not one an hour. Green with one open closes it with the green run's link. No labels, no config. Self-tested under a fake gh, a step of lint. The alarm steps cannot change the run's own result.

Same ball: `make promote-changelog VERSION=0.0.17`, the version the open release PR proposes, so the hold clears.
