Scenario: lane KNOWLEDGE, round 1. One conversation in a notes workspace ran 94 transcript commits under the shipped `compaction.intermediate: {trigger: every_n_commits, n: 20, extract_bytes: 32768}`. Four checkpoints fired and all four landed a `compaction base` commit. None reclaimed anything.

MEASUREMENT

Message files in the branch tree at each landed compaction base:

    618d5a92  messages/ = 21   summary/001.md
    87b9c7f6  messages/ = 41   summary/002.md
    2608c79c  messages/ = 61   summary/003.md
    4317fbef  messages/ = 81   summary/004.md

The worker's own prompt over the same span, read off the provider's `input_total_tokens` on each model entry, is monotone and never drops at a checkpoint:

    8021, 9628, 10561, 11078, 11341, 11480, 13870, ... 44349, ... 66434,
    ... 84262, ... 90940

CAUSE

Across the whole run the compactors made exactly TWO `mark_for_deletion` calls, and both named a prior summary:

    {"path": "summary/001.md"}
    {"path": "summary/003.md"}

Not one transcript entry was ever nominated. `souls/compactor.md` explains `mark_for_deletion` as nominating "a file on this branch", warns which two paths it declines, says "Scope deletions to files within the dispatching branch's diff", and closes with "Prior summaries under `summary/` are in your context: read them, carry their signal forward into what you write, and mark the one you supersede for deletion."

The only deletion the soul names is the superseded summary. It never says the point of the pass: nominate the `messages/NNN` entries the summary now stands for. The model does exactly what it was told, and compaction becomes pure addition — a haiku dispatch carrying the whole inherited transcript, one summary written, zero bytes freed, four times over.

EXPECTED

A landed compaction reduces the branch's composed context. Per docs/DESIGN_CONTEXT_ECONOMY.md the span before the compaction point squashes and the live tail replays; that squash is only a saving if the entries are gone from the tree.

SEVERITY

p1: the whole context-economy feature is inert as shipped, and it is not silently inert — it costs a model dispatch per checkpoint with the full transcript as its prompt, so it makes the run more expensive while making the prompt no smaller. It is also the reason a long knowledge session degrades: nothing bounds the transcript.

REMEDY SHAPE (not a fix, this is triage)

One paragraph in `souls/compactor.md` naming the transcript entries as the deletion target, and a landing-side assertion that a compaction which nominated no transcript entry is a no-op worth reporting rather than a base commit worth writing.

SECOND, SMALLER WASTE IN THE SAME PLACE

Every compactor's first act was `bash`, refused with "\"bash\" is not callable by a compactor: it is declared only because the inherited transcript references it." One wasted model call per compaction. Filed separately.
