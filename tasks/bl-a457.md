Round-1 multitenant lane.

## Gesture

A root conversation dispatched two children with `dispatch(role="worker",
name="Builder", …)` and `name="Speccer"`. Reading the root's transcript back
from a seat, every message a child sent is attributed by its full agent id:

    [deliv from=20260906T0341..Z-<8hex>-20260906T0341..Z-<8hex>]
      SPEC.md has been written and the full spec sent to Builder.

and inside `Builder`'s own transcript every deposit from its sibling reads the
same way. The word `Speccer` appears nowhere in the attribution.

## Why this is a defect and not a preference

`dispatch`'s own input schema says of `name`:

    A name is the child's identity in every surface — it is stored under the
    child, told to the child itself, and is what `message` accepts in place of
    the child's agent id — so supplying one keeps the identities and tasks in a
    subagent tree clear

"the child's identity in every surface" is the contract, and the transcript is
the surface that matters most: it is what an operator reads to audit a
cooperation, and it is what the model itself reads back as context. The id is
~60 characters of timestamped hex; the name is one word. On a phone seat the id
is the row header and consumes the whole line.

## Expected

The `from` on a delivered entry names the display name where the sender has
one, with the id available beside it (the id stays the durable handle once the
agent is dead and the name no longer resolves).

## Severity

p3 — nothing is wrong, it is just unreadable exactly where readability is the
product. Filed beside the p1 on this same run, which is the same two agents.
