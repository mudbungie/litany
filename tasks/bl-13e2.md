Round-1 daily lane. litany 0.0.10 under yog 0.0.38, worker `claude-sonnet-5`.

A conversation started with the bare rung (no `--cwd`) was given a goal naming an absolute directory in prose: "... The repo is at ~/proj/lernie — read its README.md and docs/DESIGN.md and src/ layout, then write REPORT.md in that repo root."

`bash` obeyed the prose and ran in that directory. `apply_patch` did not: it resolves against the agent's own worktree. Nothing told the model that the two tools stand in different places, and it spent the rest of the conversation failing to reconcile them. Verbatim from `messages/`:

    028  apply_patch  {"input":"*** Begin Patch\n*** Add File: REPORT.md\n*** End Patch"}
    029  tool_result  Exit code: 0
                      {"status":"applied","files":[{"path":"REPORT.md","op":"add"}]}

    030  bash         {"command":"cd ~/proj/lernie && rm -f REPORT.md && ls REPORT.md 2>&1"}
    031  tool_result  Exit code: 2
                      ls: cannot access 'REPORT.md': No such file or directory

    032  model text   "Now let me write the content directly with a heredoc via bash, since
                       apply_patch's add-file syntax with content seems finicky here"
    032  apply_patch  {"input":"*** Begin Patch\n*** Add File: REPORT.md\n+# lernie — Architecture Report\n+\n+Placeholder\n*** End Patch"}
    033  tool_result  Exit code: 1
                      litany tool apply_patch: add REPORT.md: file already exists; update it or delete it first

The model concludes its own patch syntax is at fault. It is not: the file it added is in the worktree, the file it deleted was in the project, and the refusal it gets names a file it has just watched `rm` remove.

The conversation went on to burn 4,060,308 tokens, dispatch three compactors, and leave a 0-byte REPORT.md in the worktree and nothing at all in the project.

The control: the SAME model, the SAME goal shape, started with the path rung — `{"op":"prepare","payload":{"rung":"path","dir":"<repo>"}}` — which sets `--cwd` and prepends

    Working directory: <repo>
    Do all work there, by absolute path. Do not rely on the current directory.

finished in eight steps and about a minute, wrote a good changelog to the project root, and dispatched nothing.

Expected: the two file-touching tools agree on a root, or each says which root it used in its own result. `apply_patch`'s result already prints `{"status":"applied","files":[{"path":"REPORT.md",...}]}` — a relative path, in a message where the model has just been reading absolute ones. Printing the resolved absolute path would have ended this in one step. A `cd` performed with the `cd` tool would presumably move both; a `cd` inside a `bash` command moves one, and nothing says so.

Severity p2: the cwd rung is the fix and it exists, so this is the failure mode of the path an operator takes when they do not know about it (and from the `lernie` CLI they cannot take the other one — filed separately in lernie). It is expensive and it ends in confident nonsense rather than an error.
