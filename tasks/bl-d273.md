Ruling 3 of the round-1 triage (campaign repo rounds/1/TRIAGE.md). Origin: yog bl-baed — an agent with the shipped bash grant found `litany config` on the world's PATH, wrote a fake EDITOR and committed facts.md to config/default; souls/*.md and role model/provider were rewritable the same way, so the learning loop's staged-proposal veto is walkable. Invariant: the config lineage a conversation is born on is advanced only by the operator (or by an accepted proposal the operator accepted), never by a step of that conversation. Mechanism: the verbs that write a lineage (`config`, `proposal --accept`, anything else that commits to refs/litany/config/*) refuse when LITANY_TOOL_ID is set in the environment (the marker every tool spawn already carries since bl-e8d7), with a message naming the proposal path as the lawful route. Document it in ARCHITECTURE.md beside LITANY_TOOL_ID and in DESIGN_LEARNING_LOOP.md's veto section. Test: a config write under LITANY_TOOL_ID is refused and the lineage is unchanged; the same write without it succeeds.
