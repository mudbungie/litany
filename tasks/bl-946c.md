From bl-5afc (c4e2ef4b): plan mode is a lineage — a declared, unbound `planner` role — and the delegated form (dispatch(planner)) works in a stock workspace, but the whole-conversation form needs a `litany config` pass per workspace because a root conversation always resolves the `worker` role. Decision: yes, add the verb-surface change: `litany prompt --role <name>` (and retarget) births a root on a named role from the same config commit, no new lineage; the parity checker's constraint on src/cmd/mod.rs (300 cap) is the cost — split along the seam the checker allows. yog then exposes it on the prepare rung so a seat can start a planning conversation in one act.

---

Premise correction on the cost this ball priced: src/cmd/mod.rs was 220 lines, not at the 300 cap, and adding --role to two verbs left it at 220 (the arg doc rides each verb's own Args). The parity checker needed no accommodation either: it derives a verb's argument set from clap and compares it to the public fields of that verb's Args, so a new pub field on prompt::Args / retarget::Args is picked up rather than fought. Two other files did cross the cap and split along their real seams: src/prompt/retarget/mod.rs -> preflight.rs (the verb's pre-flight and the Marks it answers with, leaving mod.rs the boundary landing), and src/prompt/role/validate.rs -> validate/tests.rs.
