From bl-5afc (c4e2ef4b): plan mode is a lineage — a declared, unbound `planner` role — and the delegated form (dispatch(planner)) works in a stock workspace, but the whole-conversation form needs a `litany config` pass per workspace because a root conversation always resolves the `worker` role. Decision: yes, add the verb-surface change: `litany prompt --role <name>` (and retarget) births a root on a named role from the same config commit, no new lineage; the parity checker's constraint on src/cmd/mod.rs (300 cap) is the cost — split along the seam the checker allows. yog then exposes it on the prepare rung so a seat can start a planning conversation in one act.
