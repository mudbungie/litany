Operator ruling 2026-08-31: the engine operates by workflows — named
declarations of what happens at every step (the basic agentic loop,
compaction, when to do what). A workflow determines the next step, so it
must be switchable on the fly; ship a "basic agentic loop" default that is
byte-for-byte today's behavior; a second workflow must be cheap to add and
safe to switch mid-conversation.

Survey: litany already holds the concept — ARCH §6 workflow.yaml is the
named what-happens-next policy (bindings, compaction clock, retry, budgets,
tool_output, tool_control), interpreted per hop, and §6 calls it "the
primary surface for experimentation"; §9.3 experiments are workflow-config
variants. What fails the ruling is switchability: the workflow is frozen at
fork and the only exit is retarget — a re-fork (rebase-forward, re-derived
dispatch commit, a child's transfer as the price). That is a migration, not
a switch.

Keystone (this ball):
- workflow mark: refs/litany/workflow/<agent-id>, a STANDING per-agent ref
  naming the config commit whose workflow.yaml governs from the agent's
  next step boundary on. Content keeps one home (config commits); the mark
  only selects which commit answers. Nearest-in-descent inheritance
  (self, then parent_of chain) so marking the root switches the tree.
- resolution seam: resolve_worker reads workflow.yaml from the marked
  commit when a mark stands, else the governing config commit (today's
  path, byte-for-byte — the whole suite pins equivalence). Per-step by
  construction: advance resolves fresh every hop.
- verb: litany workflow <ws> <agent> --config <name> | --clear.
  Validity before the mark (workspace/agent/lineage exist; target head's
  version + workflow.yaml parse). Clearing deletes config, not code.
- docs: ARCH §6 amendment (fixed-for-life sentence gains the mark),
  TAXONOMY workflow stance + basic agentic loop (= template/workflow.yaml,
  the declaration every workspace's config/default freezes — named, not
  changed).

Gates: tests (100%, all pass), docs (ARCH/TAXONOMY/DESIGN updated),
alignment (coherent against ARCHITECTURE, PRINCIPLES, TAXONOMY).
