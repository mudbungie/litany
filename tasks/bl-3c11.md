Scenario: lane KNOWLEDGE, round 1. Workspace bound to a notes corpus. The user said, in one message:

"Remember this durably, so that a completely NEW conversation in this workspace knows it without being told: <one sentence>. Use whatever facility this harness gives you for durable memory and tell me exactly what you used and where it is stored."

WHAT THE MODEL HAD

The shipped worker grant: apply_patch, bash, cd, dispatch, load_skill, message, python, read_file, search_history. None of them writes a fact. `facts.md` lives at the root of a config commit and its only writers are the human verb `litany config` (which opens $EDITOR) and an accepted reviewer proposal (DESIGN_LEARNING_LOOP §3). Nothing in a tool description mentions it.

WHAT THE MODEL DID INSTEAD

Over roughly 40 tool calls, four dispatched subagents and about seven minutes:

1. `find / -xdev -iname "MEMORY.md"` across the whole box,
2. read the harness's own `docs/ARCHITECTURE.md` out of a source checkout it happened to find,
3. grepped ARCHITECTURE for `facts.md`,
4. found `litany config` on PATH, ran it with `EDITOR=true` and got "config/default unchanged: the edit changed nothing, so no config commit was authored",
5. wrote a shell script that writes `facts.md` into whatever directory it is handed, set it as $EDITOR, and ran `litany config <workspace>` — advancing the lineage.

It worked, and it reported honestly what it had done. But the act it performed is a control-plane write that the learning loop exists to keep out of an agent's hands (filed against yog as a separate ball).

THE MECHANISM ITSELF IS GOOD

A brand-new conversation, told "answer from what you already know, without reading any file and without running any tool", answered correctly with zero tool calls. `facts.md` pinned into every new branch off the lineage works exactly as designed, is scoped per workspace, and is versioned in git — which is a better story than either comparator (Claude Code writes an unversioned per-project markdown file; hermes-agent writes one unversioned markdown file global to the whole profile). Only the writing is missing.

EXPECTED

An agent asked to remember should either be able to, or be told plainly that it cannot. Two shapes, both already half-built:

- A `remember` (or `propose_fact`) tool that stages a `facts.md` patch on `proposal/<agent-id>`, settled by the existing `litany proposal --accept`. The branch, the freshness check, the class filter (`facts.md` is already an admitted path) and the operator verb all exist; only the tool is missing. It gives the user the veto the design wants and removes the motive for the escalation above.
- Failing that, a sentence in the worker soul saying durable facts are the operator's to write and how to ask for one.

SEVERITY

p2: it is the central verb of a knowledge workspace and it is absent; a capable model will find a way, and the way it finds is worse than any tool you would have shipped.

COMPARATORS, same prompt, same corpus: Claude Code recorded it in 18.6 s with one tool call to `~/.claude/projects/<slug>/memory/`; hermes-agent in 13.9 s with one `memory` tool call to `~/.hermes/memories/MEMORY.md`. Both recalled it in under 8 s in a fresh session.
