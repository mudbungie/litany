The window trigger and its denominator both ship (bl-a537: brazen 0.0.9 stamps context_window on every usage event; litany reads it off the newest model entry). What has not moved is the shipped default: template/workflow.yaml still declares every_n_commits: 20, and docs/DESIGN_CONTEXT_ECONOMY.md section 5.1 names the flip to window_percent n: 50 as the intended end state.

The one thing standing in the way is the decline, and it is deliberate: a provider row that states no context window is refused at the boundary under window_percent, so flipping the default refuses every such workspace at its first step. So this ball is a survey before an edit — which built-in brazen rows state a window today, what a row that does not looks like to an operator, and whether the shipped default may assume one.
