Round 1, lane comparator.

State of the tree. ARCH §6 builds whole-tree budgets — `max_total_tokens`,
`max_wall_seconds`, `max_depth` — checked at every model-call boundary and at
every dispatch fork, derived from disk at each check, with every attempt segment
billed including failed and superseded ones. Then §6 *Nothing ships bounded*
(operator ruling 2026-08-16) records that `template/workflow.yaml` declares no
`budgets:` block at all. Confirmed in the tree: the shipped template has none.

So out of the box, a system whose central verb is "dispatch a child" — where
"background agents are the default shape" (ARCH §2.5), a parent never blocks, a
child may dispatch its own children, and stopping a parent does not cascade —
has no token ceiling, no wall ceiling, and **no depth ceiling**, which §6 itself
calls "the tree`s only prohibition on growth".

The comparators. Claude Code ships `--max-budget-usd <amount>` — "Maximum dollar
amount to spend on API calls" — a hard ceiling in the unit the operator actually
manages. hermes records `estimated_cost_usd`/`actual_cost_usd` per session with
an honest `cost_status` of `actual|estimated|included|unknown`, though nothing
stops on it. codex has neither. So the suite is not last here on mechanism — it
has the best mechanism of the four and the weakest default.

Why this is worth a ball rather than a shrug. The ruling that nothing ships
bounded is defensible for a single `litany prompt`: a cap the operator did not
choose is a mystery failure. It reads differently for a fanned or fleeted tree,
where the operator is not present for the spend and the growth is
multiplicative. The two cases are not the same shape, and the template treats
them as one.

Proposed shape, smallest first, and no new mechanism. `max_depth` alone. It is
the one budget whose exhaustion is not a spend judgement but a structural one —
a tree deeper than, say, 5 is a runaway, not a preference — and unlike a token
cap it cannot cut off legitimate long work. A depth default costs one line of
`template/workflow.yaml`, is severable by deleting that line (ARCH §3.6`s own
test: removing a default deletes config, not code), and leaves the token and
wall ceilings exactly as the 2026-08-16 ruling left them.

If more than that is wanted, the next rung is a `budgets:` block in the FANNED
and FLEETED paths only, which is a yog question rather than a litany one, since
`/fan` and `/fleet` are yog gestures. Filing here because the mechanism, the
template and the ruling are all litany`s.

Filed p4: a default, not a defect.
