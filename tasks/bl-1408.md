**Agent-session URL** — a vendor console link to one recorded harness
conversation, carrying that conversation's identifier in its path. "Session"
here is the vendor's own product word inside a quoted term and inside the
ported rule name `session-artifact`; it is not the interaction-span sense
banned by `docs/ARCHITECTURE.md` §2.1.

Operator ruling 2026-08-30: agent-session URLs are BANNED from all published
text in these repositories — ban them, no reason to allow it.

WHAT WAS FOUND, and it was found in the seat rather than here. Such a URL sat
in the body of a pull request on the seat repository (lernie bl-9fbe), put
there by harness convention. It is permanent: the forge keeps a body's edit
history and serves `refs/pull/<n>/head` forever, so an edit buys the false
assurance a history rewrite buys elsewhere. The remedy for what is out is
nothing; the remedy for the next one is a rule.

THE RULE DOES NOT SEE IT, HERE EITHER. `scripts/leak-rules.sh`'s
`session-artifact` pattern is near-byte-identical across four repositories, and
none of the four names the URL form. Its resource-prefix alternation does not
carry the prefix that URL used, and it has no alternative at all for a URL path
shape.

WHY IT MATTERS THOUGH THE TEXT IS IN NO TREE. The gate is what an author is
judged by at the moment of writing, and the same identifier lands in a commit
message and a pull-request body out of one habit. The commit message IS
scanned, so the hole is not confined to the place it was found.

THE FIX. Two alternatives on `session-artifact`, each with its own fixture line
so a dead one cannot hide behind a live one: the missing bare-id prefix joins
the resource list, and the code-session URL path shape catches an id under that
path whatever its prefix. Fixture lines carry the `notreal` marker; `clean.txt`
gains the near-miss and must keep not firing. Rule text stays byte-identical
with the three sibling tables, the divergence being one comment line naming the
local ball.

THE POLICY HALF. `AGENTS.md` gains the standing ruling: pull-request titles and
bodies, issue text, review comments and release notes never carry an
agent-session URL or a conversation identifier, and the harness convention of
appending one to a pull-request body is overridden here. No gate can reach a
pull-request body; that half is the author's.
